## 第一步 多轮会话

- 使用 Streamlit 聊天气泡保留用户原话与回答。
- 每个会话对应独立 ID；每轮聊天有自己的 turn ID，每次底层执行仍有独立 investigation/request ID 和调用预算。
- SQLite 保存原话、补全后的问题、回放时间、历史回答、经过封闭类型编码的结果快照、上下文解析记录与会话状态。
- 侧栏支持新建、切换、清空、显示恢复码和输入恢复码。
- 刷新或服务重启后，需要主动输入恢复码恢复。没有把凭据放进 URL，没有向新浏览器列出全库会话；当前浏览器仅能切换它已获授权的会话。
- 恢复码由随机 ID 与高熵随机令牌组成，数据库只保存令牌哈希；读、清空和删除都校验访问凭据。
- 清空需要勾选确认；删除是逻辑删除，不承诺磁盘级安全擦除。没有新增账号系统、加密数据库或多人公网服务能力。
- 乐观版本检查拒绝陈旧会话状态覆盖新状态。只读工具不因此变成写工具；高并发调度与费用级去重不在此阶段实现。

## 第二步 追问理解

### 结构化上下文

保存当前话题、固定地点 House Mill、回放时间、上一轮有效问题、预测 run_id、评估版本／范围及“通俗表达”偏好。上下文不保存模型推测出来的水位、MAE 等事实数值。

当前支持峰值、实测水位、MAE、内部 Caution／Warning／Severe、旧传感器、预测方法与 House Mill 背景等登记话题。新的、未登记的完整问题仍交给原来的路由与问题图；不强行塞进旧话题。

### 处理流程

1. 对用户原话先执行既有安全边界检查。
2. 提取明确话题与完整时间；只有日期、缺时区或不明确的相对日期需要澄清。
3. 对“它、刚才、继续、换一天”等追问，查当前会话的受控话题槽位。
4. 候选有多个时直接追问；不允许模型自作主张替用户选择。
5. 如启用 DeepSeek，可额外调用一次上下文分类器，仅允许返回所求属性枚举，如数值、时间、位置、局限、解释。模型不能生成任意工具名、日期或事实。
6. 程序组装可执行问题，同时保留整句原话中的否定、内部／官方范围与联网限制。原话和补全问题分别保存，可在调试区核对。
7. 重新运行原有工具／检索，不将历史回答转成 ground truth。时间改变会使旧预测和评估绑定失效；同一时间下若继承的来源绑定变化，则要求明确重查，不静默换成另一份数据。

模型分类失败会退回规则解析。寒暄不清空已经选定的话题。“以后都说简单点”只影响当前会话的表达，不跨会话建立长期画像。

## Token 和执行预算

- 上下文默认预算 65,536，可在侧栏调到 200,000；也可以用 `FLOODPRED_CHAT_CONTEXT_BUDGET` 配置。
- 目前分类器接收的是小型结构化槽位，不发送全部聊天历史。因此调大预算不意味着实际消耗同等 token。
- 估算使用 UTF-8 字节保守上界，不声称等于 DeepSeek tokenizer 或实际账单 token。
- 上下文分类输出上限默认 4,096，可通过 `FLOODPRED_CHAT_PLAN_MAX_TOKENS` 配置，程序限定在 256–32,768。
- 此次额外上下文分类最多一次、请求超时 20 秒，位于原调查预算之外；之后调查仍遵守原有最多三轮、八次工具调用及总超时规则。没有把 token 充足解释成允许无限循环。
- 既有回答阶段的输出上限未改。窗口压缩、摘要和按需历史召回留给第三、第四步。

## 如何启动和测试

PowerShell：

```powershell
cd C:\UCL\CASA0016\FloodPred-Agent
.\.venv-d4\Scripts\python.exe -m streamlit run streamlit_app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true
```

如果页面已在运行，直接打开 `http://127.0.0.1:8501`。先关闭 DeepSeek 与联网，避免首次操作混入 API／网络差异。

1. 发“当时预测峰值是多少？”，再发“它什么时候到？”。应看到两轮聊天，后者重新获取同一回放范围的预测，并展示峰值目标时间。
2. 接着发“它和 MAE 有什么联系？”。应同时取得预测和评估，不能把总体 MAE 说成该次峰值的实际误差。
3. 新建对话，发“它什么时候到？”。应要求说明对象，而不是继承另一个会话。
4. 发“当时预测峰值是多少？项目内部 Warning 是什么？”，再发“它是什么意思？”。应询问峰值还是 Warning；回答“峰值呢？”后继续查证。
5. 修改时间框后提问，或发“换成2026-08-04T01:48:00Z呢？”。应按新时刻查证；若样例无对应归档，应提示缺数据，不显示旧卡。发“换成2026-08-04呢？”则需要完整时间。
6. 发“以后都说简单点”，再提项目问题。在调试区确认补全问题带有通俗表达要求。
7. 在侧栏保存恢复码，刷新浏览器后输入恢复码，验证历史及当前话题回来。恢复本身不再次调用模型；继续追问才重新取证。
8. 切换对话、确认清空；检查没有串入旧会话的卡片和绑定。恢复码无效时只提示无效，不暴露其他会话。
9. 打开 DeepSeek，单话题后再追问；在“本轮上下文解析”中查看解析来源与原话／补全问题。模糊问题仍可能要求澄清，这是正确边界，不是联网失败。
