## P1-2：检索如何改变

`app/knowledge.py` 保留原先的关键词和近似拼写路径，增加可选的本地 TF-IDF＋低秩语义向量候选排序，并对少量领域说法做透明的术语扩展，例如“安装点→传感器布置”。超过 256 条记录或 4096 个词项时改用稀疏 TF-IDF，避免大规模密集 SVD；此时不再有低秩语义扩展。这不是下载的预训练多语言 embedding 模型，因此对开放式同义改写的能力有限；它只为当前策展目录扩大候选召回。检索方法会标记为 `keyword`、`fuzzy_keyword` 或 `semantic_candidate`。向量分数不当作证据真实性、相关性或答案支持度。

来源类型、精确版本、`checked_on_or_before` 截止日期在候选评分前过滤。日期代表网页核对日或版本中的完整快照日，**不是原文发表日，更不是历史预测的 `as_of_utc`**。没有完整、可解析核对日期的记录在日期过滤时排除。资料核对日期仍可通过命令行／后端指定；按用户后续要求，网页表单不再显示该输入框。原有来源路径约束、源文件 SHA-256、PDF 文件页和原件指纹检查、同概念版本冲突拒答仍保留。官方公开网页是有 URL 和核对日期的静态摘要，不会在查询时重新抓取，也不提供当前警报。

Agent 的知识工具现在使用混合候选检索，但仍通过允许的概念 ID 精确筛选，并要求该概念只有一条经过校验的来源；因此语义候选不会直接变成回答。证据区新增资料版本、可用时的本地源文件 SHA-256 与检索方式。PDF 整理笔记总会校验本地笔记哈希；原始 PDF 只有在本机仍可找到时才会进一步核对原件指纹，不能把无原件情形说成已重新验证 PDF。直接运行 `app.knowledge_cli --semantic` 时得到的是**候选文档列表**，不是已验证的自然语言结论。

LangChain [官方检索架构说明](https://docs.langchain.com/oss/python/deepagents/retrieval)区分固定的先检索再生成、Agent 自主决定何时检索和带验证的混合流程。本项目保留 P1-1 的有界 Agent 调查，而不引入开放式无限循环；语义候选属于检索层，来源验证和预算属于执行层。

## P1-3：先用残余证据，最后才回退

`app/investigation.py` 在工具／时间／轮数／LLM 预算触顶，或来源缺失、校验失败时，检查请求的预测、水位、评估和文档证据是否齐全。若仍有已核验的证据，就以**确定性的摘录式表述**给出局部结论：标明来源 ID、查到的事实和未确认的部分，不推断两者的关系，不调用额外 DeepSeek，也不把局部回答包装成完整答案。页面标记为 `partial_verified`，trace 记录 `partial_answer`。只有一条可用证据都没有时才置入 `fallback_text`、停止生成并提示回退，trace 记录 `safe_fallback`。命令行 JSON 同时给出 `stop_reason`、`answer_status`、`fallback`、`answer`、调用次数和 trace。审计仅记状态、引用 ID 和元数据，不记录问题原文或证据正文。

局部结论和回退都不伪造缺失数据、不扩大白名单、不额外发起网络请求，也不把历史回放说成实时警报。即使未超预算，只要某个请求的资料缺失而仍有其他可靠残余资料，也会先给局部结论；完全无证据才回退。比如只查到预测峰值而 MAE 工具超限，系统可告诉你“这次预测峰值是多少”，但不会据此回答“它与 MAE 的联系是什么”。
