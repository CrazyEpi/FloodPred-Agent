## 5. D2 实现说明

`get_archived_forecast(run_id)` 用参数化 SQL 精确读取一条 run 与其预测点，不执行原服务、不更新任何数据。它交叉核对归档峰值和预测点最大值；差距大于 0.01 m 时报告数据不一致。返回结果明确区分 `internal_risk_label` 与 `official_warning_status=not_checked`。

`get_forecast_as_of(as_of_utc)` 在时区感知的 UTC 时间上比较：

1. 预测生成时间不晚于回放时刻；
2. 归档入库时间不晚于回放时刻；
3. 回放时刻尚未超过该预测有效期。

时间字符串可能有不同的小数秒精度，因此用 Python 解析时间后比较，而不是依靠字符串排序。若没有当时可用的预测，返回明确错误，不沿用过期预测或捏造新结果。CLI 默认只输出摘要；加 `--include-points` 才输出所有预测点。
