## 第三步 分层上下文

新增 `app/chat_context.py`，把上下文拆为固定规则、当前问题、受控状态、最近三轮用户原话，以及相关的较早请求摘要。

摘要采用确定性的抽取方式，不让模型自由改写事实：保留原消息 ID、原文哈希、请求摘录、话题、否定／来源／时间限定、未解决状态和引用 ID／版本／哈希。摘录截短会显式标记；完整原话仍在聊天数据库。历史回答正文不进入上下文，不把助手以前说过的数值当作事实。部分回答也标记为仍有未解决内容。

摘要按已归档原消息重建校验，只有签名和内容均一致才复用，数据库摘要被篡改时重新生成。原对话清空后，派生摘要一并删除，避免摘要重新带回已清理的信息。

预算默认 65,536，界面可调至 200,000。以序列化消息的 UTF-8 字节数作保守上界，先预留输出空间，再按优先级放入上下文；超额时整条丢弃较低优先级条目，不从句子中间切掉否定或时间。最多保留三条近期请求、十二条相关旧摘要；预算大不等于主动发送全部记录。摘要生成无需新增 LLM 调用。

上下文主要用于受控的追问属性分类、对象和时间理解；最终事实仍走现有工具、RAG 和证据关口。没有把自由聊天记忆直接注入事实答案，也没有存储隐藏推理作为记忆。

## 第四步 选择性记忆与失效

### 历史话题召回

“回到之前的峰值问题”“回到最开始的问题继续”等输入会触发当前已授权会话内的历史请求检索。关键词重合与 LSA 相关性用于选候选，明确话题作过滤；多话题不明确时澄清。“最开始”显式选择最早记录，不受最近话题抢占。

只恢复登记话题及评估范围，不复制旧答案。返回旧话题默认保留当前回放时间；只有明确要求回到旧回放时刻才恢复旧时间。高水位 MAE 与总体 MAE 的范围分开。召回目前最多查看最近 500 条请求，不是无限历史记忆。

### 排名缓存

复用范围严格限于 BM25／LSA 排名分数，默认 TTL 为 900 秒，每个会话最多保留 256 条缓存。键包括会话、回放时间／地点／评估范围、查询、候选记录、原文内容和检索算法哈希。

复用前仍执行文档读取、哈希完整性检查和过滤；来源变更、删除、版本或内容变化会拒绝或重新计算。缓存过期、损坏、时间范围改变、算法变更或换会话也不会沿用旧分数。冲突检查和结论支持核验始终执行。结构化工具、网页抓取结果和最终答案不走此缓存，因此不能据此声称全链路延迟或模型费用下降了某个比例。

### 可选跨会话偏好

侧栏提供明确确认后保存、导入、查看、停用和删除表达偏好。当前唯一长期偏好是是否少用术语、通俗中文，字段固定，不接受网页或模型写入任意画像。偏好恢复码与对话恢复码分开，仅持有相应码的人能关联或删除共享偏好。

本次还修复了共享偏好为通俗、当前会话明确要求专业表述时的覆盖关系：本会话明确选择优先。清空会话解除本会话偏好链接，不删除其他会话使用的共享档案；删除共享偏好后所有关联会话停止读取它。删除是逻辑删除，不是磁盘安全擦除。

## 启动和手动检查

```powershell
cd C:\UCL\CASA0016\FloodPred-Agent
.\.venv-d4\Scripts\python.exe -m streamlit run streamlit_app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true
```

打开 `http://127.0.0.1:8501`。本次已启动本机服务。先关闭 DeepSeek 和联网，进行以下操作：

1. 问“当时预测峰值是多少？”，再问“本批次MAE是多少？”，然后“回到之前的峰值问题”。应回到峰值话题并重新查证。
2. 问“回到之前的问题”，若出现多个不同话题，应要求澄清；“回到最开始的问题继续”应能指定最早话题。
3. 连续提问至少六轮，打开调试模式的“本轮上下文解析”，查看 `summary`、`context_assembly`、`history_recall`、`rank_cache`。这些是上下文诊断，不是事实证据。
4. 将上下文预算调低到 2048，继续长对话；查看 retained／dropped 计数，确认核心问题保留，没有模型无依据地补齐缺失历史。
5. 在侧栏“跨会话表达偏好”勾选通俗中文与确认，保存偏好。新建对话后应沿用；当前对话发“以后请专业一点，使用术语”应能覆盖它。
6. 保存偏好恢复码，另开浏览器会话后导入；不导入时不能看到或使用别人的偏好。可停用当前链接，或凭偏好码删除共享档案。
7. 确认清空对话后，再问“回到之前的峰值问题”，应提示找不到，不从摘要或排名缓存恢复已清理的历史。
8. 有 API key 时重新开启 DeepSeek，验证相同追问在规则与模型协作下仍保持来源核验；模型分类超时会退回规则。

不要为了手动测试删除真实知识原文或业务数据库；来源篡改和删除测试只操作临时测试副本。
