## 2. 实际实现

### 状态与身份

- 独立数据库：默认 `state/investigations.sqlite3`；`state/` 被 Git 忽略，不使用预测、声纳或其他已有业务库。
- 每次调查独立执行 ID、随机恢复凭证及图 thread ID。恢复码与该 execution 绑定，不能用另一调查的凭证恢复它。
- 原问题、两个时间条件、限制及数据路径保存为不可覆盖的恢复上下文；恢复 API 不接受这些条件的新值。
- 操作系统文件锁阻止同一调查并发恢复，进程退出后锁释放。

### 保存格式

新增 `checkpoint_codec.py`，使用版本化、类型白名单 JSON 保存 QueryResult、Pydantic 数值模型、问题图、候选、证据、自定义 dataclass、tuple 和 frozenset。未知类型、字段漂移及不兼容版本拒绝恢复，不使用 pickle 或动态导入。

客户端、API key、连接、live budget 不序列化；QueryResult 的原始模型思维链字段在编码时移除。问题、证据和候选属于检查点内容，保存在本机状态目录，不写进 Git。已完成调查再次读取返回历史快照，不重新调用工具，也不代表重新核验今天的来源。

### 持久预算与恢复

绝对 UTC 截止时间包含暂停和停机；默认 60 秒。工具和模型调用在操作前持久扣减，恢复加载累计值，不重新发放额度。闲聊回复也在调用前扣减，并兼容原 core 的回复后计数，避免重复计费。实际失败不退还已预留额度。

图使用同步节点检查点；节点结果先写入执行记录，再交给图保存。若结果已记录但图检查点尚未提交，恢复复用该结果。如果节点中途崩溃，调用结果未知，则保留额度，停止自动重复调用，只整理前一已保存边界的证据，停止原因 `interrupted_inflight`。

恢复前检查数据文件元数据、知识版本及相关来源；必要的精确引用校验沿用原证据门。文件或版本变化时移除受影响证据并重新校验，停止补查，返回 `source_changed`。目录丢失也不会继续使用旧文档结论，仍有效的已保存数值可以形成局部回答。

评估文件路径新增可选注入参数，首次查询和数值补查均使用保存的路径，避免 CLI 与 UI 或重启进程采用不同数据模式时混用评估来源。默认参数 None 保留普通运行行为。

### 幂等审计与入口

普通 `run_investigation()` 仍临时执行并使用原 JSONL 审计。持久入口使用状态库的 `floodpred_audits`，每个 execution 一条最终摘要，以 upsert 处理重复执行／重新校验，避免跨 JSONL 和状态库形成重复记录。

`start_persisted_investigation()` 和 `resume_investigation()` 经兼容模块导出，UI 与 `app.checkpoint_cli` 共用。Streamlit 增加保存进度选项与恢复码入口，普通模式默认不变。CLI 提供 start、resume 及真正启动另一 Python 进程的 demo。

## 5. 能力边界

- 恢复到整个已保存节点，不从任意代码行或 HTTP 内部继续。未知调用可能已在外部执行但没有可保存结果，因此停止重发，保留前一边界及已扣预算。
- 不承诺外部 API exactly-once、不启用自动重试／后台续跑或并行工具。
- 时间上限仍是协作式检查，使用本机 UTC 时钟，不是进程级强制中止。
- 恢复码是本机调查访问凭证，不构成带账号登录的多租户授权系统；状态库属于本机可信存储。
- 234 项通过是本轮场景验证，不是所有问法、来源变化和操作系统故障的穷举。

当前可以表述为“支持 SQLite 检查点持久化与节点边界恢复，保留回放时间和已消耗额度，并验证跨进程恢复及局部回答”。
