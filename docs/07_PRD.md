# 简版 PRD：FloodPred 历史回放问答

## 目标与用户

目标是在不恢复云服务器的前提下，让面试官或项目评审用一个本地界面核查：某个 UTC 时刻系统**当时可见**的预测与水位是什么，项目内部术语如何定义，以及模型评估究竟测量了什么。主要用户是技术产品、数据或 Agent 岗位评审，不是现场防汛值班员。

## 用户故事与验收

1. 问“当时预测峰值是多少”：返回归档峰值、预测目标时间、`run_id`、内部风险等级和历史回放标识；生成及入库时间不得晚于 `as_of_utc`。
2. 问“本批次 MAE 是多少”：只取结构化快照，展示数值、米单位、评估版本、样本范围和匹配点数；明确这是事后评估，不是当时已知数据。
3. 问“项目内部 Caution 是什么”：返回经过 SHA-256 核验的来源与章节，并写明它不是官方 Flood Alert；证据区注明服务端原文使用 Watch。
4. 问混合问题：分别走数值工具和文档检索；不得用语言模型猜数值。
5. 问危险或无依据问题：拒绝修改数据、发布警报、泄露密钥；文档缺失、版本冲突和越过时间闸门时显示失败原因。
6. 用自然表达问“项目内部 warning 是什么”“项目内部 Caution 是什么”：识别组合意图；界面统一称 Caution，证据区保留服务端和论文原词。

## 范围与非目标

P0 包括显式路由、三个只读数值工具、文档检索、可选 DeepSeek 主题补全与短解释、Streamlit 界面、审计 trace、离线评估。非目标包括实时模型推理、实时官方警报查询、自动发布 MQTT、House Mill 专属 SOP、未经离线／线上范围限定的洪水事件检出率声明，以及生产级权限系统。

## 衡量方式

固定 20 条离线验收案例记录每题期望与实际；另跑自动化测试。通过率仅指该小样本内的路由、数值、引用和拒答行为，不外推为洪水预测质量。业务风险底线是：错误时不把“没有证据”说成“无风险”。

## 取舍

目前用普通 Python 显式路由而非 LangGraph，因为流程同步、无需人工暂停与恢复。文档范围窄，使用关键词＋元数据和哈希校验而非向量库；数值通过只读结构化数据，不经 RAG。LLM 只解释已有证据且默认关闭。该取舍降低误路由与演示依赖，但意图覆盖、语义检索和复杂多轮工作流有限。
