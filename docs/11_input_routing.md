# 问题如何被识别，DeepSeek 何时参与

1. 用户问题先经过安全边界：明显的数据库修改、警报发布、密钥索取或绕过指令在任何工具和模型调用前拒绝。
2. 勾选 DeepSeek 后，它先输出一份很短的 JSON 任务计划：这是项目问题、寒暄、普通聊天，还是需要澄清？项目问题需要哪些只读工具和文档主题？每一项必须关联用户原问中的片段，工具和主题也必须在白名单里。计划只是建议，程序检查后才执行。本地确定性命中不能被模型删掉；模型失败则退回本地路由。
3. 对项目问题，程序分别读取归档预测、历史声纳、带固定哈希的评估快照，或经版本与来源校验的文档。一个问题可以有多条路径。“预测峰值和 MAE 的联系”会分别取某次预测峰值及事后批次 MAE，然后解释它们不是同一层级的误差。
4. 取证完整后，DeepSeek 根据证据包写一段面向非技术志愿者的解释。回答必须列出全部证据 ID，数字只能来自证据正文，不能补写实时状态、官方警报或现场行动指令。机械校验并不能证明完整语义正确；仍应查看“证据从哪来”。任一步失败时展示已取得的原始资料，不让模型猜缺失部分。
5. 纯“你好”走介绍；与项目无关的普通问题可做一般对话，但标明未使用 FloodPred 资料；像“项目那档警戒”这样的含糊项目问题应先追问。普通对话不能拿来宣称项目事实。

数值始终来自三个只读工具，而不是 DeepSeek。有本地 API key 时页面默认勾选开关，否则默认关闭；可手动切换。关闭后只走旧的确定性路由，普通闲聊不会调用模型。启用后项目问题通常有一次规划与一次综合回答调用；普通聊天有一次规划与一次聊天回答调用。模型计划不是安全证明；模糊输入仍可能误路由，应在“证据从哪来”复核。

## Caution 的显示别名

项目界面把内部 4.20 m 档统一显示为 **Caution**。检索键 `internal_watch`、服务端 README 的 **Watch**、原始摘要和引用 ID 保持不变，以便复核；论文的原词是 **Caution**。该显示别名不能反向证明服务端文档写过 Caution。

## 英国官方公开资料何时出现

标签 `official_public_guidance` 只是来源类型的中文显示名，不会自行触发检索。明确询问“官方 Flood Alert 是什么”等静态定义时，路由到 `official_flood_alert`，再从知识目录读取 GOV.UK 条目的已整理摘要和来源链接。链接型条目没有本地原文摘录，不能充作实时警报；“现在的官方 Flood Alert 是什么”在工具调用前拒绝。不能把内部 Caution / Warning 等同于 Environment Agency 的正式类别。

## DeepSeek 思维链

新规划与综合解释请求开启低强度 thinking。API 若返回 `reasoning_content`，调试区按阶段显示原始文字；它可能包含推测或错误，不是检索证据，也不写入 JSONL 审计日志。无返回时调试区明确说明没有可展示的思维链。
