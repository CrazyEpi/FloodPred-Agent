# 问题如何被识别，DeepSeek 何时参与

1. 用户问题先经过安全边界：明显的数据库修改、警报发布、密钥索取或绕过指令在任何工具和模型调用前拒绝。
2. 本地规则识别确定性信息：预测峰值、历史实测水位、MAE 数值。它也识别常见文档主题，如项目内部 Watch/Warning、论文的离线事件评估与部署期限制。一个问题可以同时命中多条路径；因此“预测峰值是多少？项目内部 warning 是什么”会分别读归档数据库与服务端 README。
3. 只有用户勾选 DeepSeek 开关时，模型才会尝试补全模糊的**文档主题**。它只能从固定 concept 白名单返回最多三个主题，且需给出用户原问中的逐字片段；不能自己创造工具或返回答案。像“项目那档警戒”无法唯一判断是 Watch 还是 Warning 时，允许返回空结果并请用户说清楚；“超过 4.43 米时项目怎么分级”可归入内部 Warning。
4. 每个文档主题再经过来源类型、版本、路径、文件哈希与章节核验。缺失、改动或版本冲突时不调用解释模型。
5. 通过核验的文档片段与**用户原问**一起发给 DeepSeek。返回 JSON 必须含正确引用 ID、可在片段中逐字定位的引文；解释中的数字不能超出该片段，部分未经证实的行动／官方状态表述会被拒绝。失败时只展示已核验事实。官方 GOV.UK 链接型条目没有本地原文摘录，因此目前只给静态定义，不用模型补写。

数值始终来自三个只读工具，而不是 DeepSeek。主题识别可扩大问法覆盖，但模型置信度不是安全证明；未经覆盖的同义词仍可能拒答或误路由，重要结论应在“证据从哪来”标签复核。默认不开启 API；勾选后可能先有一次主题识别调用，再对每条文档证据分别做解释调用，产生费用。
